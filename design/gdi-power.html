Win32 GDI 的真实上限 —— 被低估的系统绘图全家桶

设计稿把 GDI 当成"只能 FillRect + 1px 线 + 硬阴影"的 1995 年水平。实际上系统自带 msimg32（AlphaBlend / GradientFill）、gdiplus.dll（抗锯齿矢量/渐变刷） 和 UpdateLayeredWindow（逐像素半透明窗口）——全部零依赖、纯 C 可调。下面每个效果都标注了真实 API 路径，最后合成一张完整面板概念。

01真·软阴影

旧认知：offset 实心矩形
实际：柔和的多层阴影
AlphaBlend × 预计算 32bpp alpha 阴影位图
做法：启动时生成一张径向渐变 alpha 的圆角阴影位图（或 3-5 层不同半径/透明度），绘制时 AlphaBlend 一次盖章。静态预计算 + 一次调用，成本≈0。

02半透明面板 + 磨砂玻璃

面板悬浮在桌面/聊天窗之上
UpdateLayeredWindow（逐像素 alpha 窗口）
做法：整个窗口用 32bpp DIB + UpdateLayeredWindow 呈现，任意圆角/异形/半透明，边缘天然抗锯齿；"磨砂"= 面板打开瞬间截取桌面区域 StretchBlt 降采样 + 半透明遮罩叠一次（经典 trick，静态成本）。

03线性 / 径向渐变

GradientFill（msimg32）· GDI+ LinearGradientBrush / PathGradientBrush
做法：GradientFill 原生支持多色 stops 的水平/垂直渐变；GDI+ 另有径向/路径渐变（高光按钮、发光强调条）。均为系统 DLL，一次初始化后每帧只画缓存位图。

04抗锯齿圆角、圆环与曲线

锯齿（旧认知）
75%
🐱
GDI+（GdipDrawArc 抗锯齿）· 或 2x 超采样 + StretchBlt 缩小
做法：gdiplus.dll 的 flat API（GdipSetSmoothingMode）给所有圆/弧/曲线开抗锯齿；不想引 GDI+ 就把 GDI 画到 2x 内存位图再 StretchBlt 缩一半 = 全场景抗锯齿（二手工惯例）。

05点阵纹理 · 光晕强调（克制地发光）

高频 ✦ 37 次
做法：点阵 = CreatePatternBrush（7×7 单色位图做刷子，零运行时成本）；光晕 = 预渲染的径向 alpha 位图 + AlphaBlend 叠在强调元素下。用于"高频"标签、选中态、进度环——点到为止，不做全屏光污染。

效果GDI 家族能否实现真实路径 / 代价
软阴影✔ 完全可以预计算 alpha 阴影位图 + AlphaBlend 盖章；静态资源，运行时几乎免费
半透明 / 异形窗口✔ 完全可以UpdateLayeredWindow；注意 EDIT 子控件需改自绘或 WS_EX_LAYERED 子窗口（工程量 +1）
磨砂玻璃（实时背景模糊）◐ 假磨砂可以打开瞬间截桌面降采样 + 半透明遮罩（静态）；实时模糊超出 GDI——除非再借 d2d1.dll 的 GaussianBlur（也是系统自带、零依赖，严格说已不算 GDI）
线性/径向渐变✔ 完全可以GradientFill（msimg32）/ GDI+ 渐变刷；每帧重画渐变也不贵，且可缓存成位图
抗锯齿圆角/圆/弧/文字✔ 完全可以GDI+ 一行开平滑；或 2x 超采样（无新依赖，内存×4 依然小）
点阵/纹理填充✔ 完全可以CreatePatternBrush，原生
发光/Glow✔ 可以（预渲染）径向 alpha 位图 + AlphaBlend；不支持任意实时参数化的辉光，但 UI 发光本来就应是静态强调
每帧实时高斯模糊 / 粒子系统✘ 不行这是唯一真正的边界；硬要的话 d2d1.dll 的 effect 管线（系统自带）可以做，但架构就变 D2D 了
