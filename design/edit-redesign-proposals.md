# 「管理模式」重设计——细化方案与 UX 审查

> 2026-09-19 · 响应用户反馈：管理模式太重、修后缀/去重意义不明、想要右键编辑弹窗（加标签/加索引文字）、文件名淡化。本文档给出 3 个细化方案（A 编辑弹窗 / B 检视抽屉 / C 全上下文化）+ 横切设计（数据模型/搜索/导入/键盘导航），每案附 UX 审查。
>
> **2026-09-19 选型结果：用户批准 B（检视抽屉）+ 横切全套，已在 05-swiss 实现（见其 NOTES.md「v3 抽屉与横切」段）。「管理模式」概念从产品中移除。**

## 0. 先回答：为什么之前都做成「同窗口双模式」

这是 v0.6 的架构决策遗留（HANDOFF 有记录），不是产品必然：主面板是 UpdateLayeredWindow 逐像素分层窗口，**分层窗口里的 EDIT 子控件不可见**（v0.4 血泪），所以输入框全部自绘；管理需要输入（重命名）+ 大网格，当时为避免「第二张 ULW 合成表面 + 焦点往返」选择了同窗切换模式。10 个变体全部继承了这个骨架——所以你看到它们「统一」如此。本期重新评估：**第二个真窗口、抽屉、纯菜单在工程上都可行**（成本与取舍见各方案），双模式不再是被架构锁死的唯一解。

## 1. 问题诊断与任务频率分析

用户反馈翻译成设计语言：

| 痛点 | 本质 |
|---|---|
| 管理模式跟主窗口一样、切换重 | **频率错配**：把中低频任务（整理）抬成了一整个高频界面（模式） |
| 修后缀/去重看不懂 | **面向问题的工具暴露在界面上**：用户没带着问题来，工具就成了噪音 |
| 想要右键编辑：加标签+加索引文字 | **就地、单对象、轻量**的元数据编辑诉求 |
| 文件名淡化 | 文件名是存储概念不是使用概念；用户在乎的是「找得到」（索引）和「分得开」（标签） |

任务频率（决定 UI 层级的依据）：

- **发送：每天几十次**——零摩擦，主路径不许动
- **打标签/索引文字：集中在导入后的整理期**（批量为主），偶尔单张补
- **删除：偶尔**；**重命名：极少**（用户不关心文件名）
- **去重/修后缀：几乎从不主动**——应自动化或藏到维护菜单

## 2. 成熟产品调研（怎么做元数据编辑）

- **Everything**：无任何管理模式。搜索即筛选，右键是菜单，没有「整理界面」概念
- **Eagle / Billfish（素材管理器）**：检视面板（inspector）就地编辑标签，支持多选批量打标；没有模式切换，只有选中态
- **macOS 访达**：⌘I 检查器是独立小窗；标签是就地彩色点
- **Raycast**：列表 + 选中项动作菜单，无第二模式
- **QQ/微信表情管理 / Telegram 贴图管理**：极简——只有删除/置顶，没有标签没有索引（说明表情工具的「整理」需求真实存在但被主流 IM 忽略了——这正是 MemePanel 的空间）
- **Google Photos**：信息面板侧滑就地编辑描述/人物

**共性结论**：① 没有产品用「整窗切换的管理模式」做元数据编辑；② 主流是三级递进——**菜单（单动作）→ 检视器（单对象多字段）→ 批量选中态**；③ 维护性操作（去重/修复）全部藏在菜单深处或自动执行；④ 导入时刻是打标签的黄金窗口。

## 3. 方案 A：「贴纸编辑窗」（你的直觉方向，细化）

右键格子 → 弹出独立编辑小窗（约 340×430 逻辑 px，光标右侧出现，屏幕边缘自动翻转）：

```
┌────────────────────────────┐
│  [128px 预览 · 白衬纸方角]   │
│────────────────────────────│
│ 标签                        │
│ (动物✓)(猫猫)(+ 新标签)     │  ← chips 点击 toggle；+号点开内联输入
│────────────────────────────│
│ 索引文字                    │
│ [ 开心 猫 熟睡____________ ] │  ← 自绘输入框（复用现有代码），空格分词
│────────────────────────────│
│ capybara.jpg        ↗位置  │  ← 文件名 8.5px 灰（淡化）+ 打开所在文件夹
│                     [删除]  │  ← 红字，二次确认武装 3 秒（沿用现有模式）
└────────────────────────────┘
```

- **自动保存**（无确定按钮，像 macOS 检查器）；Esc / ✕ / 点外部关闭（点外部=保存关闭）
- **批量**：主面板 Ctrl+点击多选 → 右键 → 标题变「已选 3 张」→ 标签操作应用全部；索引文字给「追加 / 替换」小开关
- 重命名不再有专门入口——文件名行点击可改（就地，低频动作放在低频位置）

**工程**：第二个真窗口。两条实现路径：
- **A1** = 再造一张 ULW 表面（透明玻璃质感）——成本高（复制整套合成+焦点管理）
- **A2（推荐若选 A）** = 普通 `WS_POPUP` 窗口 + GDI+ 自绘，**不透明、方角、白底黑框**——瑞士语言零损耗（Swiss 本来就是方角纸白），工程量约为 A1 的 1/3。输入框/IME 复用现有自绘代码搬到新 wndproc

**UX 审查**：
- ✓ 就地、单焦点任务、无模式感；完全符合「右键=编辑这个」的心智模型
- ✓ 真窗口可拖走（双屏对照整理场景佳）；弹窗寿命短（用完即关），不积累窗口负担
- ✓ 单张打标签 = 2 步（右键→点 chip）
- ✗ 批量入口（Ctrl 多选）可发现性弱——需要在面板加选择态视觉提示
- ✗ 焦点/IME 在两窗口间往返（自绘输入框代码可复用，但状态恢复要细心）
- ✗ 弹窗可能遮住网格（决策：默认出现在光标右侧并自动让开网格）
- 结论：**合理**，体验上限高（尤其对照整理），工程量中等

## 4. 方案 B：「右缘检视抽屉」（inspector，推荐）

右键格子 → **面板右缘向右展开 300px 抽屉**（同一个窗口加宽，无第二窗口）：

```
┌──────────────────────────┬─────────────┐
│ 搜索 [____________]       │ [96px 预览]  │
│ ════════════════════════ │─────────────│
│ ALLE TIERE KATZEN        │ 标签          │
│ ──────────────────────── │ (动物✓)(猫猫) │
│ ▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦  │ (+ 新标签)    │
│ ▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦  │─────────────│
│ ▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦  │ 索引文字       │
│ ▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦  │ [开心 猫___]  │
│ ▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦▦  │─────────────│
│ （网格继续可浏览/多选）     │ cat.jpg [删] │
└──────────────────────────┴─────────────┘
```

- 面板整体加宽 300px（窗口 resize，已有能力），网格重排列数（瑞士网格天然支持）
- **网格与抽屉同时活**：左边继续滚/多选，抽屉内容跟随「最后右键的对象」；多选时抽屉顶部「已选 N 张」，标签操作批量生效
- Esc / 右键空白处 / 再点该格子 = 收起；打开抽屉期间主路径（点击=发送）在网格区完全不变
- 自动保存同 A

**工程**：**零新窗口**——同一张 ULW 表面加一个布局态（panel_layout 加 drawer 分支），焦点不出主窗口、IME 无切换、无第二套合成代码。三个方案里最省。

**UX 审查**：
- ✓ 零窗口管理、零焦点切换——三个方案里认知负担最低
- ✓ **对照式整理体验最佳**：左浏览右打标，连续整理 20 张不需要任何导航（右键→打标签→右键下一个），这是「整理期」真实工作流
- ✓ 批量最顺：Ctrl 点 5 张 → 右键 → 抽屉一次打标；或抽屉开着逐张右键扫过去
- ✓ 与「≤2 秒发送」零干扰：不右键就永远见不到抽屉
- ✗ 面板变宽在屏幕右缘可能出界（解决：展开时窗口左移补偿，已有 SetWindowPos 能力）
- ✗ 窗口宽度跳动有一瞬重排感（ULW resize 已处理过类似场景，可加 150ms 宽度过渡）
- ✗ 不能把编辑器拖到第二屏（方案 A 才行）
- 结论：**最合理**，工程与体验双优；唯一牺牲是「拖走对照」

## 5. 方案 C：「全上下文化」（最激进的架构革命）

取消一切「编辑界面」——菜单即编辑器：
- 右键 → 标签子菜单（每项带 ✓ toggle，尾部「+ 新标签…」）+「索引文字…」（格下原地展开小输入浮层，像 Windows 重命名）+「删除」「打开位置」
- 多选 = Ctrl 点击，浮出小操作气泡（标签/删除/取消）
- 界面常驻成本 = 0，最瑞士

**UX 审查**：
- ✓ 界面最静、理念最纯，Swiss 极简的极致
- ✓ 「原地重命名式」输入浮层是桌面用户 30 年肌肉记忆
- ✗ **批量打多标签体验差**：菜单 toggle 后需保持打开（要自绘菜单，HMENU 做不到）——工程成本反超抽屉
- ✗ 菜单层级 +1；一次只能操作一个标签
- ✗ 索引文字是自由文本，藏在菜单第三层不利于「想到就补一句」
- 结论：**理念成立、工程性价比最低**——自绘菜单的成本足够做抽屉，收益却更少。作为思想实验保留；若未来做「超极简模式」可回访

## 6. 横切设计（无论选哪个方案都要做）

1. **数据模型 v2**：Entry 增加 `indexText`（变长 UTF-16，可空）；index.bin 升 MP_VERSION 2。**必须写 v1→v2 迁移**（读入 v1 后补空字段重存）——不能依赖现在的「版本不符→整体丢弃重扫」路径，那会丢掉全部标签。
2. **搜索语义**：匹配 = 标签名 ∪ 索引文字 ∪（文件名 ⊕ 开关）。**默认包含文件名，托盘菜单「搜索：包含文件名」可关**。
   - 为什么不做「导入时逐张选择」：导入时弹选择是最低效的打断（导入往往一次几十张）；全局开关一次设定长期受益——QQNT 乱码名场景关掉它，认真命名的库打开它。
3. **hover 显示淡化**：格子底部白条优先显示「索引文字（无则文件名）」，8.5px 灰——文件名从「主角」降为「兜底」。
4. **修后缀/去重撤下主界面**：修后缀改为**每次扫描静默自动执行**（无损修正，用户永远不需要知道它存在）；去重移入托盘菜单「维护」子菜单（手动触发，结果仍用选中态呈现）。两个按钮从产品词典消失。
5. **键盘导航**（正交升级）：方向键在网格移动选中框、Enter 发送选中项——不依赖鼠标的速发路径，弥补所有方案的鼠标依赖。
6. **导入打标黄金窗口强化**：文件夹拖入自动建同名标签（已有，保留）；导入完成后 toast「已导入 12 张 · 已打标签「猫猫」」，点击 toast 直接打开抽屉校对。
7. 关于指令面板的补充：其「不紧凑」来自 56px 行高与元数据行。若未来回访，紧凑变体 = 40px 行（仅缩略图+名称）+ 顶部保留 2×4 快捷格（最近项）——列表负责搜索、快捷格负责盲发，两者互补而非互斥。

## 7. 推荐

**B（检视抽屉）+ 横切 1-6 全套**，并从产品词典删除「管理模式」一词——它变成「右键编辑」。

理由汇总：工程最省（零新窗口零新表面）× 整理期工作流最优（对照式连续打标）× 主路径零干扰（不右键不见它）× 批量体验最好。牺牲的「拖走对照」是双屏用户的窄场景，未来想要时可以低成本补一个「抽屉弹出为窗口」按钮（B→A 混合，抽屉内容即弹窗内容，代码同构）。

若你更认同「编辑就该是个独立窗」（A 的心智模型更直白），选 **A（A2 不透明方角路径）**，成本可控且瑞士风无损。

选定后我可以：先出静态高保真（无头截图直接看抽屉/弹窗全态），再实现交互——仍全程无头可验。
